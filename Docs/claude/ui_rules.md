# Правила UI и графики (обязательны)

Требование пользователя: **никаких растянутых/сплющенных картинок** («деформируются — выглядит ужасно»).

## Как это обеспечено в коде
- `Editor/UiBuild.cs`:
  - `Img()` — любой спрайт вписывается в рамку **в родных пропорциях** (`Fit`), `preserveAspect = true`.
  - `Sliceable` — единственные спрайты, которые можно резать 9-slice: `ui_progress_frame`, `ui_progress_fill`,
    `brd_slot_glow`, `brd_slot_outline`, `brd_belt_tile`, `ui_tile_button`, `ui_tile_button_flat2d_generated`.
    **Критерий:** у спрайта по краям нет рисунка. Украшение в углу можно (углы 9-slice не тянутся), украшение
    **посередине стороны** — нельзя: оно размажется. Поэтому `ui_panel_popup` (сердечко снизу, зелёная полоса
    сверху) и `ui_panel_card` (листья на торцах) режутся **не** 9-slice, а ставятся целиком.
    Промты на чистые плашки для пользователя — `D:\Work\ЯндексИгры\Docs\UI_PROMPTS_ЧистыеПлашки_ВсёПоПолкам.txt`.
  - `ByHeight(sprite, h)` / `ByWidth(sprite, w)` — размер по одной стороне с родными пропорциями. Использовать их.
  - `Button()` — рамка кнопки = пропорции спрайта; подпись в одну строку (автоуменьшение), не заезжает на иконку,
    область подписи — внутренние 76% (края кнопок декоративные: кант, «гвоздики» у ui_btn_secondary).
  - `Anchor()` не перезаписывает размер искажённо.
- `ProjectSetup.SliceBorders()` — снимает границы 9-slice у кнопок/плашек/ценников/облачков.
- `SceneValidator` («Проверить сцены») — ругается на картинку не в пропорциях, 9-slice вне списка,
  надпись, не влезающую в рамку, и **содержимое окна, вылезшее с кремового поля `ui_panel_popup`**
  на деревянную раму или зелёную полосу. Исключения (они на раме по замыслу): `Title`, `Ribbon`, `Close`, `Glow`.
  Проще не подбирать числа руками, а увеличить ширину окна в `PopupShell` — высота посчитается сама.

## Размеры картинок для WebGL (27.09.2026)

Стороны любой текстуры кратны 4 и не больше 2048. Иначе Unity не может сжать её в DXT/crunch и кладёт
в билд несжатой: из-за этого билд весил 64 МБ вместо 40. После добавления графики —
`python Tools/ArtPipeline/fix_tex4.py` (добивает прозрачными пикселями поровну с двух сторон,
слои ремонта пересчитывает в RenoLegoData.cs). Кнопку при смене размера менять по пропорции спрайта:
ширину — только вместе с высотой.

## Если текст не влезает
Уменьшить текст (autoSize) или увеличить картинку целиком. Не менять пропорции картинки.
- `Text(..., autoSize: true)` ставит `overflowMode = Truncate`: **без этого TMP не ужимает текст по высоте**
  и строки вылезают за плашку (так вылезало облачко обучения).
- «Проверить сцены» ругается на надпись, которая не влезает в рамку даже на минимальном кегле.
- Белым можно писать только по тёмному. Середина ленты `ui_ribbon_banner` кремовая → заголовки окон
  и экранов пишем тёмным (`Dark`), рамка текста — 68 % ширины ленты, иначе длинный заголовок уходит на завитки.

## Надписи на лентах
Лента изогнута — прямая строка на ней смотрится наклейкой. Вешаем `TextArc` (`Editor/SceneBuilder.Arc()`):
парабола подъёма `bend = высота ленты * 0.077`, поворот крайних букв `tilt = 6°`. Компонент пересчитывает
вершины только при смене текста/кегля, так что на производительность не влияет.

## Текст в узких плитках (26.09.2026)
TMP с автоподбором ужимает текст только по высоте рамки. Если выключить перенос строк
(`enableWordWrapping = false`), длинная надпись останется одной строкой и вылезет за плитку —
автоподбор её не тронет. Поэтому для подписей внутри плиток перенос оставляем включённым,
а рамку делаем по высоте под нужное число строк.

## Растяжения и 9-slice (23.09.2026, вечер)
- Ничего не тянуть. Если картинку рисуют мельче, чем она нарисована, 9-slice оставляет края в
  пикселях спрайта — торцы полос и уголки плашек «плющатся». `UiBuild.Img` для нарезанных спрайтов
  ставит `pixelsPerUnitMultiplier = высота спрайта / высота на экране`, и края масштабируются.
- Спрайт, который в игре показывают крупнее, чем он нарисован, надо перерисовать, а не растягивать:
  так было с `ui_panel_popup` (380 точек на 1300 на экране) — промт на крупную версию в паке 23.09.
- Иконка, которую подставляет код (`icon.sprite = ...`), обязана получать `preserveAspect = true`.

## Ремонт, альбом и магазин (23.09.2026)
- Экран ремонта районов 1–4 — один кадр магазина на весь экран плюс слои улучшений из того же кадра.
  Слой рисуется в своём размере из кадра (`preserveAspect = false` здесь законно: размер родной).
  Карточки — полосой внизу, рядов столько, сколько улучшений (`RenovationScreen.LayoutCards`).
- Альбом — три слоя: стол, ровная книга, ленты-закладки. Книгу не наклонять, закладки не вращать.
- Магазин — содержимое ложится на плашки, нарисованные на `bg_shop`. Координаты плашек считаются по
  самой картинке (светлые прямоугольники), а не подбираются на глаз: `ShopBig/ShopTop/ShopMid/ShopLow`.
- Прозрачные PNG не должны попадать в «полнокадровые» в `ArtImportPostprocessor`: у них снимается
  альфа и прозрачный фон становится чёрным.

## Полосы, ползунки и фоны-прилавки (22.09.2026)
- Полоса прогресса и ползунок — только `ui_bar_track` (жёлоб) + `ui_bar_fill` (белая заливка, цвет задаёт код)
  + `ui_bar_knob` (ручка). Середина у них ровная, поэтому 9-slice не искажает рисунок.
  Старые `ui_progress_frame/fill` (цветы и листья по краям) не тянуть.
- Экран магазина — нарисованный прилавок `bg_shop`: плашки уже есть на картинке, своих карточек не рисуем,
  раскладываем содержимое по координатам плашек (`ShopBig/ShopTop/ShopMid/ShopLow` в SceneBuilder.Hub).
- Закладки альбома идут вдоль наклонного края книги и повёрнуты на её угол (`CoverTilt`, `CoverEdgeX`).
- Ценники на карте расставляет скрипт по дороге (`Tools/ArtPipeline/map_nodes.py`), руками не двигаем:
  при замене картинки района достаточно перезапустить скрипт.
